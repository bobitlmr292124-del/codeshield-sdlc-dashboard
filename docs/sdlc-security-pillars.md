



CodeShield SDLC Security
Pillars



 



The Software Development
Life Cycle (SDLC) consists of stages involved in planning, developing, testing,
releasing and maintaining software. CodeShield organizes its security framework
around five pillars.



 



1. Endpoint/IDE Security



This pillar focuses on
securing developers' computers and development environments. Potential threats
include malware, exposed secrets and insecure development tools.



 



2. Version Control
System (VCS) Security



This pillar focuses on
protecting source code repositories and version control systems. Potential
threats include unauthorized access, leaked credentials, exposed secrets and
malicious code changes.



 



3. CI/CD Pipeline
Security



Continuous Integration
and Continuous Delivery (CI/CD) systems automate software building, testing and
deployment. Security concerns include stolen pipeline credentials, insecure
workflows and unauthorized deployment.



 



4. Registry Security



Software registries
store packages, dependencies and container images used by applications. Risks
include vulnerable dependencies, malicious packages and tampered images.



 



 5. Production Security



Production security
focuses on protecting deployed applications and their running environments.
Risks include unauthorized access, insecure configurations, exposed services
and unpatched vulnerabilities.



 



Relevance to CodeShield



 



These five pillars
provide a structured way to understand security risks throughout the software
development lifecycle. The CodeShield dashboard can help users view and
organize the security information and incident records supported by its current
implementation. The presence of a pillar in the framework does not
automatically mean that its security checks or external integrations have been
implemented.



 



 Conclusion



 



Considering security at
every stage of the SDLC can help development teams identify risks earlier and
improve software protection. CodeShield provides a dashboard for organizing
relevant SDLC security information, within the limits of its implemented features.
